\section{Monitoring Dashboard}
\label{sec:ui}

The React dashboard (Next.js, TypeScript, Tailwind) gives full visibility into
every pipeline run without touching a terminal. It starts automatically with
\texttt{python run.py}.

\subsection{Command Center}

The primary page. A user uploads a PDF or photo, picks a company, and clicks
Run. The file goes to the n8n webhook; the UI polls \texttt{GET /trace/\{doc\_id\}}
every 500\,ms and lights up the stage cards as each agent completes:

\subsection{Operations — Document Table}

A searchable, auto-refreshing table of every processed document. Columns:
supplier, date, document number, HTVA / TVA / TTC amounts, account code assigned,
decision, and processing time. Clicking a row opens a detail drawer with the full
step trace, line-item table, RAG chunks with similarity scores, and validation
result. An \textbf{Export CSV} button downloads all fields as a spreadsheet.

\subsection{Intelligence — Scores and RAG}

Shows measured retrieval and agent scores, while the dedicated Skill History
section reports SkillOpt's live status, selection score, model-token usage,
step decisions, previous runs, and versioned runtime skills. Only a strict
held-out gain can promote a proposed skill. The manually authored v003 Coder
experiment remains separate from the library's extractor optimization.

\subsection{Email and Drive intake}

The active n8n workflow includes Gmail attachment and Google Drive file-created
branches. Each source normalizes supported PDFs and images into the same
pipeline as webhook uploads. Those polling nodes remain disabled in the local
instance until Google OAuth credentials and the watched Drive folder are
configured; the setup steps are in \texttt{n8n/INTAKE\_SETUP.md}.

\subsection{Systems — Health Monitor}

Real-time polling of FastAPI, n8n, Qdrant, and the LLM endpoint with green/red
status indicators. Any degraded component is immediately visible.
